## 3. Validation Logic

1. **JSON 解析：** 使用浏览器内置 `JSON.parse`；语法错误或顶层不是对象时停止后续检查。
2. **字段契约：** 检查 `province`、`city`、`level1`、`level2`、`level3` 均存在且为字符串；除 `city` 外不得为空。
3. **业务规则：** 对照完全虚构的三级分类树检查路径。它不是保险公司的业务规则。
4. **原文证据：** 对非空的 `province` 和 `city` 做原始文本的字面包含检查，缺少匹配时给出警告。

任一检查失败，最终闸门为“已拦截”；只有警告时为“需要人工复核”；四项均通过时为“可进入人工复核”。最后一种状态不证明业务事实正确。

## 4. Test Cases

在本地浏览器逐项选择场景并点击“运行校验”。

| 案例 | 预期 | 实际 | 结果 |
| --- | --- | --- | --- |
| 01 正确输出 | 四项通过；可进入人工复核 | 四项均显示“✓ 通过”，闸门显示“✓ 可进入人工复核” | PASS |
| 02 分类路径错误 | 业务规则失败；已拦截 | `$.level3` 显示“分类路径非法”，闸门显示“× 已拦截” | PASS |
| 03 缺少原文依据 | 原文证据警告；需要人工复核 | `$.city` 显示“缺少原文依据”，闸门显示“! 需要人工复核” | PASS |
| 04 缺失字段 | 字段契约失败；已拦截 | `$.level3` 显示“缺少必填字段”，后续检查跳过，闸门显示“× 已拦截” | PASS |
| 05 JSON 格式错误 | JSON 解析失败；页面保持可用 | 解析显示“× 失败”，后续检查跳过，闸门显示“× 已拦截” | PASS |
| 06 多个问题同时存在 | 分类失败、证据警告；已拦截 | `$.level3` 和 `$.city` 分别显示对应问题，闸门显示“× 已拦截” | PASS |

补充交互检查：编辑已校验的输入后显示“结果已过期”并清空旧问题；切换场景后显示“尚未运行”；重置后两个输入框为空；空输入运行时闸门显示“已拦截”且四项检查跳过。关于窗口正常开关，浏览器未记录脚本错误。`node --check app/app.js` 通过。

在 1440×900 和 1600×900 浏览器视口检查了三栏布局、中文标题、最终闸门和字段路径。两种尺寸均无页面横向溢出或关键内容裁切；1600×900 时页面与校验区均无需纵向滚动。

## 5. Privacy Audit

- `.gitignore` 保持排除 `private_sources/`；Stage 1 当前跟踪文件列表中没有该目录。
- 对拟提交的 `README.md`、`app/`、`docs/` 与 `.gitignore` 搜索手机号、身份证格式、邮箱、IPv4、URL、内部 ID 字段、路径及 API 相关标记；未发现真实号码、地址、凭据、内部参数或原始截图。文档中出现的 `user_id` 等仅是禁止公开项目的通用名称。
- 检查 `app/`：没有 `fetch`、`XMLHttpRequest`、`sendBeacon`、`WebSocket`、外部脚本或浏览器持久化调用。输入只在当前浏览器页面内处理。
- 演示文字和分类树均为重新虚构的教学案例；页面关于说明明确写出实习结束后的成果转化及非公司生产系统性质。

## 6. Known Limitations

- 分类树是虚构示例，不代表真实保险业务规则。
- 原文证据仅做简单字符串匹配，不能进行语义推理，也不能证明事实为真。
- 本工具不是正式规则引擎或生产系统，不调用真实 LLM。
- 页面刷新后输入不保留；浏览器内校验不能替代人工复核。
