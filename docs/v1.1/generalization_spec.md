# v1.1.0 — Generalization Spec

> Stage 3A 设计稿。只规定下一阶段的最小实现；本阶段不修改 App、`main`、Pages 或 `v1.0.0` tag。全部新案例均为公开虚构内容。

## 1. v1.0.0 的问题

当前 [`app/app.js`](../../app/app.js) 在全局写死 `requiredFields = [province, city, level1, level2, level3]`、一棵保险演示分类树，以及只检查 `province`／`city` 的证据逻辑。现有场景下拉只替换同一字段集合的输出。访问者输入 `product`、`problem`、`action` 等其他业务 JSON 时，合法 JSON 仍会因缺少保险字段而被阻断。根因是**校验规则与案例数据没有分离**，与公开通用工具的定位不符。

## 2. v1.1.0 目标

让同一条轻量校验流程读取当前 `validationConfig`，检查任意领域的**顶层 JSON 对象与所选字段**。保留 HTML、CSS、Vanilla JavaScript、GitHub Pages、浏览器本地处理和现有三栏 Console；不接入 LLM、后端或公司内部规则。明确展示已执行、跳过和未配置的检查，避免把“没有检查”画成“通过”。

## 3. 模板模式

顶部新增“模板／自由”模式切换。模板模式的场景下拉提供六个虚构领域案例，每个模板独立携带 `sourceText`、`modelOutput`、`validationConfig`，字段和规则随场景一起切换。选择模板时一次性载入三者并清除旧结果；可编辑两段输入以观察结果变化。配置在模板模式中可查看但不作为主要操作。六个模板的字段与预期结果见 [`template_spec.md`](template_spec.md)。

## 4. 自由模式

自由模式不预设保险字段。用户编辑原始材料、任意顶层 JSON 对象和一个简明“校验配置”：必填字段、原文证据字段、允许值。配置使用普通字段名列表和允许值行，不要求手写 JSON Schema；其内部结构见 [`validation_config_spec.md`](validation_config_spec.md)。模式切换保留本次会话中的自由草稿，不上传、不持久化；任何输入或配置修改都令旧结果显示“结果已过期”。“重置”清空自由模式的输入与配置；模板模式的“载入示例”恢复当前模板。

## 5. UI 改动范围

- 保留现有三栏、结果区、四个检查节点和主按钮；只在顶部加入模式切换与模板下拉。
- 自由模式提供一个紧凑的“校验配置”入口，打开小型侧栏或弹层，填写逗号分隔的字段列表及“字段／允许值”规则行。主画面仍以原始输入、模型输出、校验结果为中心。
- 配置入口显示简短摘要，例如“3 个必填 · 3 个证据字段 · 1 条允许值规则”。模板模式可显示只读摘要，让用户知道当前检查范围。
- 节点除通过、警告、失败、跳过外，增加**未配置**。结论汇总分别统计这些状态，并说明“可进入人工复核”只覆盖已配置且实际运行的检查。
- 保留当前桌面三栏和移动端纵向可用性；不做视觉重设计。

## 6. Validation Engine 改造范围

将硬编码字段、分类树和地区证据列表从 `runWorkflow` 中移走；校验函数只接受当前 `sourceText`、`modelOutput`、`validationConfig`。保持 `JSON.parse` 与顶层对象检查。字段契约按 `requiredFields` 检查；业务规则按 `enumRules` 逐字段检查；原文证据按 `evidenceFields` 对非空标量做字面包含检查。没有规则的节点显示“未配置”。配置先做自身校验，避免无效或互相矛盾的配置产生假阳性；不执行用户编写的代码或表达式。

## 7. Gate semantics

| 条件 | 最终闸门 | 说明 |
| --- | --- | --- |
| 输入、配置、JSON、字段契约或枚举检查失败 | 已拦截 | 指明失败来自输出还是配置；前置失败使依赖节点“跳过”。 |
| 无失败，但证据检查警告 | 需要人工复核 | 仅表示缺少原文直接字面依据，不断言值错误。 |
| 至少一项字段／规则／证据检查已配置且执行，所有已配置检查通过 | 可进入人工复核 | 同时列出“未配置”节点；不代表真实业务事实正确。 |
| 只有 JSON 解析运行，其余检查均未配置 | 需要人工复核 | 明示“仅完成格式解析，尚未配置内容检查”。 |

`跳过`与`未配置`都不计入通过数。配置不存在的节点保持“未配置”；已配置但因前置失败未执行的节点显示“跳过”。即使闸门为“可进入人工复核”，人工仍需判断事实和业务适用性。

## 8. 非目标

不实现完整 JSON Schema、AJV、嵌套路径规则、跨字段组合规则、复杂 DSL、正则编辑器、规则脚本、语义匹配、LLM 事实核查、真实保险规则、上传、账号、云保存或生产自动决策。`enumRules` 仅检查单字段允许值，不能声称验证完整分类层级。保持全部示例虚构、脱敏；工具仍不是公司内部系统。

## 9. Stage 3B 验收标准

1. 六个模板都能载入自己的三件数据；字段集合确实不同，且各自预期结果与运行结果一致。
2. 自由模式用蓝牙耳机例子：原文和 `product/problem/action` JSON 配置后，四项检查通过；把 `action` 从“换货”改为“退款”后，枚举仍通过，`$.action` 证据警告，闸门变为“需要人工复核”。
3. 自由模式从不隐式要求 `province/city/level1/level2/level3`；非法 JSON、缺失已配置字段、非法允许值和空输入均给出清楚结果且页面不崩溃。
4. 不配置枚举或证据字段时，对应节点显示“未配置”，不计入通过；仅解析而无内容配置时不能显示“可进入人工复核”。
5. 切换模板、模式或编辑任一输入／配置后，旧结果过期；已配置但因前置失败不能运行的节点显示“跳过”。
6. 浏览器本地运行，用户输入不上传；桌面三栏和移动端基本操作保持可用；不新增框架、后端或外部 API。
