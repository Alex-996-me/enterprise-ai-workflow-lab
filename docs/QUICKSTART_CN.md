# Workflow Guardrail｜快速说明

如果你第一次打开这个项目，只需要记住一句话：

**它不是帮 AI 做决定，而是在 AI 做完决定以后，检查这份输出有没有资格继续往下走。**

## 1. 这个工具是干什么的？

假设 AI 已经把一段文字整理成 JSON。Workflow Guardrail 会在这份输出进入下游系统之前，按你选择的检查范围核对格式、字段、允许值和原文证据，然后给出“已拦截”“需要人工复核”或“可进入人工复核”。它不调用另一个 AI，也不自动批准业务结果。

## 2. 为什么需要它？

一段 JSON 即使能正常解析，也可能缺字段、使用了不允许的值，或者写入原文中根本没有直接出现的内容。格式正确，只是继续检查的起点。这个公开 Demo 源于本人实习结束后对企业 AI 工作流调研中通用问题的整理；案例和规则均为虚构。

## 3. 最快怎么体验？

打开 [Live Demo](https://alex-996-me.github.io/enterprise-ai-workflow-lab/)。默认已载入“客服意图分类”，点击“运行校验”即可看到一项原文证据警告。把模型输出中的 `urgency` 从“紧急”改成“不着急”，再运行一次：这次原文有直接证据，但“不着急”不在允许值中，因此被拦截。也可选择“IT 服务工单”：先运行，再把 `severity` 改成“低”，观察允许值检查怎样变化。载入案例不会自动运行，结果只会在你点击按钮后更新。

## 4. 四项检查是什么意思？

- **JSON 解析：** 输出是不是合法的顶层 JSON 对象？
- **字段完整性：** 要求的字段是否存在，值是否是可用的文字、数字或布尔值？
- **允许值检查：** 指定字段的文字是否在预设选项里？
- **原文证据：** 某些关键值是否在原始材料里逐字出现？没找到只表示“缺少直接证据”，不能据此断言它是错的。

如果某项没有设置检查范围，页面会显示“未配置”；如果本来配置了，但前一步失败导致无法检查，会显示“跳过”。这两种状态都不算通过。

## 5. 自定义输入要准备什么？

切换到“自由模式”，页面会先载入蓝牙耳机案例。你可以编辑左侧原始材料和中间的 JSON，再打开“校验配置”：在“必填字段”和“原文证据字段”里用逗号分隔字段名，在“允许值”里每行写一条，例如 `action = 换货 | 退款 | 维修`。保存后主界面只显示配置数量摘要。先用“换货”运行，再把 `action` 改成“退款”，就能看到原文证据警告。配置、输入和结果都只保留在当前浏览器会话中，不上传。

## 6. 什么输入适合？

适合顶层 JSON 对象中的信息抽取、分类、标签和状态判断。字段名尽量简单明确；要做原文证据检查的关键值，最好能在原始文字中直接找到。

## 7. 什么输入暂不适合？

目前不支持嵌套字段规则、复杂跨字段条件、语义推理、自动事实核查，也不能判断合同是否合法、文案是否专业或业务决定是否合理。允许值只是单字段列表，不是完整业务规则库。

## 8. 为什么“全部通过”仍要人工复核？

工具只能证明**已配置、已执行**的这些机械检查没有发现问题。原文中出现同一个词，不一定代表 AI 理解了上下文；未配置的方面也没有被检查。因此最终状态叫“可进入人工复核”，仍由人判断事实、语境和业务适用性。

```text
原始材料
   ↓
  AI
   ↓
结构化 JSON
   ↓
Workflow Guardrail
├─ JSON 格式
├─ 字段完整性
├─ 允许值
└─ 原文证据
   ↓
人工复核 / 下游系统
```
